# Phase 5 limitations and owner actions

Historical Phase 5 local work was interrupted before publication and incorporated into Phase 6 (1.4.0-rc.1). Its daily-default descriptions refer to the earlier proposal; Phase 6 defaults to 72 hours. No v1.3.1 release was published.
This is **1.3.1-rc.1**, a research and reliability candidate. The core non-owned 100+ authentic reviews → daily stored sync → custom carousel requirement remains blocked by usable provider access and explicit storage/display rights. No newly researched vendor connector is installed. No live Menjar reviews or full 24-hour cycle were verified.

- Places remains the official limited fallback: up to five selected reviews, live request-only display, server key/billing/agreement required. No historical discovery, accumulation or stored daily archive. Counts show the last validated selection, not a real-time total; zero/empty responses do not validate.
- Business Profile needs an approved project and managed verified business. Its secondary owner dashboard/cache is not a non-owned public aggregation grant.
- Vendor JSON/API documentation does not itself establish upstream non-owned acquisition rights, commercial republication, permanent retention or daily/history entitlement. The comparison marks these unknowns individually rather than inferring rights from widgets.
- Existing licensed rows receive empty new provider/binding fields at upgrade and remain intact. A successful complete sync through the current permitted adapter revalidates the collection for connected/public use; do not automatically label retained rows as newly authenticated Google data. Legacy import/manual/adapter records keep their original provenance and compatible legacy widgets.
- Source/business/license changes hide stale licensed rows, including cached and legacy-widget paths. Hidden retained records are not deleted. A time-limited/deletion-required license needs a provider-specific purge implementation; the existing permanent interface must not be used to evade those obligations.
- Database architecture has no fixed total review/location quota. Host memory/storage and bounded query/widget/request limits still apply. Stored widgets default to 100 and support configured limits up to 10,000; shortcode overrides reduce the saved limit. Larger licensed collections can be stored, with display sizes bounded for hosting performance. Places live request scope remains at most five selected locations per call; more locations consume additional calls.
- No production Node/Python service was added. Production needs ordinary PHP/WordPress and database hosting. WP-Cron timing depends on traffic or a configured host cron. Fixture scale and benchmark numbers are not shared-hosting guarantees.
- Provider keys remain encrypted and private; changing WordPress authentication salts requires reconfiguration. Purge page caches when changing Places keys. JavaScript is required for live cards; never override no-store on the dynamic POST response.
- Sync statistics are cumulative per bounded collection attempt. Whole-page validation prevents importing a malformed page; database writes are not promised as an all-or-nothing multi-page transaction. Stable IDs make retries idempotent. Remote deletion is not inferred from an absent selected review.

Next actions: obtain an explicit eligible provider contract and private account/endpoint, or approve/configure a genuine Places key to validate the limited option. Confirm the actual business identity, approve any costs, test individual metadata/attribution and observe the real 24-hour cycle.
